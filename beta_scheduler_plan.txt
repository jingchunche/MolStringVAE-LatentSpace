Beta Scheduler Integration Plan
================================

1. 新增與修改的 source code 檔案
   - src/utils/beta_scheduler.py
     * 新增檔案，封裝兩種 beta 調整策略：Warmup 與 Cycling。
     * 主要介面：`build_beta_scheduler(config, max_step, base_beta)`，依 YAML 設定回傳一個可輸入 step -> beta 的 callable。
     * 內部會支援 `schedule` 參數（linear/cosine），Warmup 接收 `warmup_ratio`、`beta_max`；Cycling 接收 `num_cycles`、`cycle_ratio`、`beta_max`，並以提供的 `max_step` 計算週期長度。
     * base_beta 作為缺省值，如果設定不完整或模式不支援，就直接回傳固定 beta 的 callable。

   - src/hooks.py
     * 於檔案結尾新增 `KLBetaSchedulerHook` 類別，並在 `hook_type2class` 中註冊 key "kl_beta_scheduler"。
     * Hook 初始化：
       - 讀取設定值 `module`（預設 `-d_kl_factor`）、`base_beta`、`max_step`（若未提供則從 `config.training.variables.$max_step` 傳入）以及 `scheduler` 區塊。
       - 呼叫 `build_beta_scheduler` 取得 callable；若 `scheduler` 缺 `mode` 或建立失敗，保持 None，並用 logger.warning 提醒後回退固定 beta。
     * `ring` 方法：
       - 取得當前 step（`batch['step']`）並計算新的 beta。
       - 將 `model[module_name]` 的 `weight` 或 `bias` 更新成浮點數 beta（依據 Affine module 的結構，一般為 `weight`）。若 module 不存在或無 `weight` 屬性則 warning 並停用。
       - 把 beta 寫入 `batch['beta']` 供日誌或其它 hook 使用。
     * 不修改任何既有 hook 行為，舊 pipeline（未在 YAML 插入該 hook）不會受到影響。

   - 其他檔案
     * train.py 與現有 YAML 不需改動，只需在未來新增 hook 的 YAML 設定即可。

2. YAML 使用範例
   下面是一個完整、可複製的 YAML 片段（例如在 `training/base_beta0001.yaml` 的 `training.pre_hooks` 底下自行加入），僅在需要動態 beta 時新增：

```
training:
  pre_hooks:
    kl_beta:
      type: kl_beta_scheduler
      module: -d_kl_factor          # 可省略，預設值為 -d_kl_factor
      base_beta: $beta              # 沿用既有變數。若想覆蓋固定 beta，直接填浮點數
      max_step: $max_step           # 若有自訂訓練長度，可在這裡覆寫
      scheduler:
        mode: warmup                # 支援 "warmup" 或 "cycling"
        schedule: cosine            # 或 "linear"
        beta_max: 0.01              # 最終(或每個 cycle 平台期)的 beta 值
        warmup_ratio: 0.2           # 僅 warmup 使用：前 20% step 線性/餘弦升溫
        # 若選擇 cycling：
        # mode: cycling
        # num_cycles: 4             # 週期數量
        # cycle_ratio: 0.3          # 每個 cycle 前 30% 升溫，後 70% 維持 beta_max
```

3. 行為說明與備註
   - **預設保持固定 beta**：只要 YAML 沒有加入 `kl_beta_scheduler` hook，模型仍由 `-d_kl_factor` 中設定的常數（`base_beta` 或 `$beta`）控制 KL 損失權重。
   - **Warmup**：`warmup_ratio`×`max_step` 之前，beta 依 `schedule` 從 `base_beta`（缺省 0）平滑增至 `beta_max`；之後維持 `beta_max`。
   - **Cycling**：`max_step / num_cycles` 為一個 cycle 長度。每個 cycle 前 `cycle_ratio` 部分按 `schedule` 升至 `beta_max`，剩餘部分固定 `beta_max`。最後一個 cycle 若超出 `max_step`，會自動截斷。
   - **缺省/錯誤處理**：當 `scheduler.mode` 未設定或出錯時，hook 會以 logger.warning 提示並回退為常數 beta，不影響訓練。
   - **Forward 相容性**：僅透過 hook 更新 `-d_kl_factor`，不改動其它 module；若該 module 改名或不存在，hook 會偵測到並停用。
   - **觀察 beta**：在 `batch` 中寫入 `beta`，若已有記錄機制可將其納入 log；亦可於後續新增自訂 accumulator/hook 監控。

使用者只需依上述檔案位置新增實作並在 YAML 中選擇性加上 hook，即可完成動態 KL 權重調整。
